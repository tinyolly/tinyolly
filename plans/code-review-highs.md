# Code review: areas that deserve a `high` pass (run separately, on demand)

Date: 2026-11-09 · Scope rule: **TinyOlly platform only**. Never review the demo generators/apps (`docker-demo*`, `docker-ai-agent-demo`,
`docker-otel-demo`, `k8s-demo*`, `k8s-otel-demo`, `k8s-ai-agent-demo`), nor `docs/`, `plans/`, `site/`, `release-notes/`.

The cheap default is one `medium` review of the whole platform diff (`origin/main...origin/v3-integration`). This list is
the *separate* set of targeted `high`-effort passes to run later, one at a time, only where the risk justifies the cost.
Run each as a scoped review (`/code-review high <paths>`), and tick it off here with the outcome.

## Not worth `high`

* Frontend JS (`static/*.js`): the platform diff there is small (a status helper + imports). Covered by the `medium` pass.
* Generated/locked files: `requirements.txt` locks, `go.sum`, `k8s/otelcol-configs/**` (generated by `scripts/sync-k8s-configs.sh`).
* The deleted Redis `storage.py`.

## Process

1. `medium` pass over the whole platform diff first — **done 2026-11-09**, findings and verdicts in `plans/code-review-medium-2026-11-09.md` (8 findings: 3 real defects, 2 maintenance gaps, 1 accepted, 2 false alarms). The confirmed cleanup-script bug raises the priority of H6.
2. Pick high-pass items from the table by what the medium pass suggests; run them one by one and record the outcome in the Status column.
3. Add `/security-review` for H4/H5 before any release.
