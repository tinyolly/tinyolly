# Development and testing

- Python dependencies are locked: edit `requirements.in` in a service directory, then regenerate with:

    ```bash
    uv pip compile requirements.in --universal --python-version 3.13 -o requirements.txt
    ```

- Pinned versions (collector, supervisor, Ollama, OBI, Python, Go) live in `versions.env`; the Dockerfiles carry matching `ARG` defaults. Update both together.
- The architecture diagram (`docs/images/architecture.png`) is generated by `scripts/make-architecture-diagram.py`: run it with `docker/apps/tinyolly-mcp/.venv/bin/python` (needs matplotlib and Pillow).
- Lint with the pinned ruff (rules in `ruff.toml`; its defaults change between releases). There is no CI, so run checks locally:

    ```bash
    pip install ruff==0.17.4
    ruff check docker/apps/
    ```

- **All local tests**: common, UI/API, receiver, MCP server, frontend JS (`node --test`), Go, collector configs, kubectl guard. `--stack` adds the e2e run against the running stack; `--kind` adds the kind smoke test (briefly stops the compose stack):

    ```bash
    ./scripts/test-all.sh
    ```

- Individual suites:

    ```bash
    (cd docker/apps/tinyolly-common && pip install -r requirements-test.txt . && pytest tests)
    ```

    ```bash
    ./scripts/test-go.sh
    (cd docker/apps/tinyolly-ui && pytest tests)
    ./scripts/test-kubectx-guard.sh
    ```

- End-to-end (stack up, ~8 min; `--up` starts it, `--only a,b` picks scenarios, `--list` shows them). It drives OTLP through the collector, applies every preset via OpAMP and checks results through the API (test hooks: `POST /admin/reset`, `POST /api/opamp/config?wait=N`):

    ```bash
    python3 scripts/e2e.py
    ```

- OpenTelemetry Demo (demo running on Docker or kind, ~12 min; see [the demo page](otel-demo.md)): checks the data, the MCP tools, failure flags and the PII preset:

    ```bash
    scripts/test-otel-demo.py --mode docker      # or --mode k8s
    ```

- Collector configs: `./scripts/test-collector-configs.sh` (validate and start every preset); after editing them run `./scripts/sync-k8s-configs.sh`.
- Docs pages need `title`/`description` front matter (the MCP server lists them).

## Building and publishing images

The start scripts pull images from Docker Hub (`tinyolly/*`). To run your own changes, build locally; to publish, use `build/dockerhub/`.

| Goal | Command |
|---|---|
| Run core from this checkout (Docker) | `docker/01-start-core-local.sh` |
| Run the TinyOlly AI SRE Agent from this checkout (Docker) | `docker/05-start-sre.sh [--demo]` (always builds the agent) |
| Load core images into kind | `build/local/build-core-kind.sh` |
| Build and deploy the agent on kind | `k8s/06-rebuild+deploy-sre.sh [--demo]` |
| Log in to Docker Hub | `build/dockerhub/01-login.sh` |
| Build / push core (python-base, otlp-receiver, ui, mcp, opamp-server, otel-supervisor) | `build/dockerhub/02-build-core.sh <version>` then `03-push-core.sh <version>` |
| Build / push only the UI (quick iteration) | `02-build-ui.sh <version>` then `03-push-ui.sh <version>` |
| Build / push the agent (`tinyolly/sre`) | `02-build-sre.sh <version>` then `03-push-sre.sh <version>` |
| Build / push everything | `02-build-all.sh <version>` then `03-push-all.sh <version>` |

Builds are native-architecture and uncached and tag `latest` plus the version; `DOCKER_HUB_ORG` overrides the organization. Publishing a GitHub release runs `.github/workflows/release.yml`, which runs `02-build-all.sh` and `03-push-all.sh` with the release tag. Details: [build/README.md](https://github.com/tinyolly/tinyolly/blob/main/build/README.md).

## Testing mesh features without Istio

`scripts/seed_mesh.py` posts synthetic Istio metrics (OTLP/JSON) for an Online Boutique mesh: scenarios `baseline`, `flaky`, `fault`, `canary`, `deny`, `multicluster`, plus `--trace` (a trace through a gateway and a waypoint), `--l7 <service>` and `--ui <url>` (records a change marker). To run the Compose stack next to kind, use the second Colima VM and shifted ports (UI 5105, MCP 8865, OTLP 4418):

```bash
scripts/docker-alt.sh                      # rebuild python-base and every service, then start (docker/docker-compose.altports.yml)
python3 scripts/seed_mesh.py --otlp http://localhost:4418 --scenario flaky --ui http://localhost:5105
MCP_URL=http://localhost:8865/mcp ...      # then ask the MCP server (get_edge, what_changed, chart_map_diff)
```

## Agent eval

`scripts/agent_eval/eval.py` injects a known fault, lets a local model investigate through the MCP tools, and grades the answer against ground truth (service, cause, evidence). Five scenarios including a healthy control, on Compose (seeded metrics) or kind (real faults from the Istio demo repo). Needs Ollama (`LOCAL_BASE`, `LOCAL_MODEL`); results go to `eval-results.json`.

```bash
python3 scripts/agent_eval/eval.py --target docker --repeat 3
python3 scripts/agent_eval/eval.py --target kind --scenarios flaky,deny --no-skill-hint
```

```bash
pytest scripts/agent_eval
```

## Documentation images

Screenshots are generated, not hand-pasted. `scripts/make-doc-images.py` screenshots the UI tabs (headless Chrome) and saves the MCP chart images, each twice: a preview (max 900 px wide) in `docs/images/` and the full size in `docs/images/full/` (what a click opens). The OpenTelemetry Demo shots come from `scripts/make-otel-demo-images.py`.

```bash
scripts/make-doc-images.py                       # all shots from the running stack (UI :5005, MCP :8765)
scripts/make-doc-images.py --only mesh-map-diff  # one shot
scripts/make-doc-images.py --seed --otlp http://localhost:4318   # post a fault scenario first (diff and trace path)
scripts/make-doc-images.py --check               # no stack needed; also runs in test-all.sh
```

To add one, add a line to `SHOTS`, run the script, and embed it as `[![alt](images/<name>.png)](images/full/<name>.png)`, or with a width, `<a href="../images/full/<name>.png"><img src="../images/<name>.png" width="400"></a>`. Path prefixes: markdown under `docs/` uses `images/` (MkDocs rewrites it); raw HTML uses `../images/` because pages are served at `/<page>/` (except `docs/index.md`: `images/`); the README uses `docs/images/`. `--check` fails on a missing shot, a preview over 300 KB, or an embed without the click-to-expand link. Settings: `TINYOLLY_UI`, `TINYOLLY_MCP`, `CHROME`; needs Pillow or macOS `sips`.

**Before publishing the docs site** (`./mkdocs-deploy.sh` pushes to `gh-pages`):

1. `scripts/make-doc-images.py --check` passes.
2. The build is clean with warnings as errors (a "target is not found" warning means a wrong image path):

    ```bash
    source ~/.venv/mkdocs/bin/activate
    python3 -m mkdocs build --strict -d /tmp/site
    ```

3. Open the built page and click an image: `python3 -m http.server -d /tmp/site 8000`, then `http://localhost:8000/<page>/`.

Common mistakes: a wrong path prefix (see above), not committing `docs/images/full/<name>.png` (the click opens a 404), editing a generated preview by hand.

## What is running?

`scripts/status.sh` prints, read-only and in about four seconds, the Colima VMs, containers per compose project (unhealthy ones named), the kind cluster's namespaces, Helm releases and node memory, which stacks and demos are deployed with **the command that removes each**, TinyOlly's endpoints with their service counts, and disk use.

```bash
scripts/status.sh            # everything
scripts/status.sh --short    # skip the disk and node-memory details
```

## Tear everything down

`scripts/teardown.sh` removes what `status.sh` shows, in levels; each level includes the ones above it. It is **destructive**: it prints the plan and waits for `y` (or `--yes`).

```bash
scripts/teardown.sh --level demos      # OpenTelemetry Demo (Docker and kind), Istio ambient demo
scripts/teardown.sh --level stacks     # + TinyOlly itself, Docker and kind, data volumes included
scripts/teardown.sh --level cluster    # + the kind cluster
scripts/teardown.sh --level vms        # + stop both Colima VMs
scripts/teardown.sh --level vms --prune            # also prune build cache and dangling images first
scripts/teardown.sh --level vms --delete-vms --yes # delete the VMs and their disks (data loss)
```

It only touches what this project creates and lists other containers that would stop with a VM. `--prune-images` also removes all unused images.

## Docker contexts

Two Colima VMs can coexist: `colima` (default) and `colima-tinyolly` (this project). Every script pins `DOCKER_CONTEXT=colima-${COLIMA_PROFILE:-tinyolly}`; new scripts that call `docker` must too (copy the 3-line block from any `0N-*.sh`). Ad hoc: `docker --context colima-tinyolly ...`.

## Service catalog actions (easy revert)

Per-service actions in the APM Service Catalog are a popover menu on the service name. To get back the old row of buttons, set `ACTIONS_STYLE = 'buttons'` at the top of `docker/apps/tinyolly-ui/static/serviceCatalog.js` and rebuild the UI:

```bash
cd docker
DOCKER_CONTEXT=colima-tinyolly docker compose -f docker-compose-tinyolly-core-local.yml up -d --build --no-deps tinyolly-ui
```

To remove the menu code, delete `SERVICE_ACTIONS`, `openServiceMenu`, `closeServiceMenu`, the `data-service-menu` click handler and the two `document.addEventListener` lines. The map and catalog cross-links are independent of this setting.
